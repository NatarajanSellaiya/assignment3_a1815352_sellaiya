## Project Overview
This repository contains the replication package for a small scale, domain specific Retrieval Augmented Generation (RAG) system. The pipeline is engineered to assist cybersecurity practitioners by generating actionable, fact grounded incident response guidelines. 

To mitigate "extrinsic hallucinations" inherent in Large Language Models, the system utilizes a **Hybrid Retrieval Architecture** (Dense Vector + BM25 Sparse Keyword) to extract highly technical nomenclature from an authoritative, multi modal knowledge base (NIST SP 800-53, ISO 27001, CISA STIX, and MITRE ATT&CK). The generative module relies on a locally hosted, 4-bit quantized open-source model (`Mistral-7B-Instruct-v0.3`).

## Repository Structure
* `/data/`: Contains the unstructured PDFs, structured JSON threat intelligence, and web-scraped data used to build the vector database.
* `A1815352_CyberRAG.ipynb`: The main execution pipeline, including data ingestion, chunking, retrieval, and LLM generation.
* `ragas_eval_results_final.csv`: The final automated evaluation scores generated by the RAGAS framework.
* `requirements.txt`: Required Python dependencies.

## System Architecture Highlights
1. **Knowledge Base:** Processed using `RecursiveCharacterTextSplitter` (Chunk Size: 1000, Overlap: 200) to maintain procedural context in dense cybersecurity frameworks.
2. **Hybrid Retriever:** Combines `BAAI/bge-large-en-v1.5` dense embeddings (weight: 0.6) with BM25 sparse retrieval (weight: 0.4).
3. **Generation:** `Mistral-7B-Instruct-v0.3` loaded via `BitsAndBytes` (4-bit NF4 Quantization) to run efficiently on edge-hardware (15GB VRAM).
4. **Prompt Engineering:** Iron clad constraints forcing the model to cite specific source files and strictly refuse out-of-context queries.

## Evaluation Results
The system was evaluated using the **RAGAS (Retrieval Augmented Generation Assessment)** framework with an LLM-as-a-Judge methodology across 10 practitioner queries:
* **Average Faithfulness:** 0.6000
* **Average Answer Relevancy:** 0.7251

*Note on Limitations:* The evaluation phase revealed that edge-hardware deployment (NVIDIA T4 GPUs) struggles with the massive context windows required for automated RAGAS batch processing, necessitating aggressive VRAM flushing and sequential row by row execution. Furthermore, the aggressive 4-bit quantization required for edge-deployment degraded the model's instruction following adherence, accounting for the moderate Faithfulness score.
